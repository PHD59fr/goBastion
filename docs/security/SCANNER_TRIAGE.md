## Archive length and nonce bounds

The archive AEAD generates random nonces, with 28 bytes of overhead. Each archive
uses a fresh 256-bit data key and at most 2^20 segments. Canonical header JSON is
limited to 64 KiB. Chunk sizes are 1 through 2^20 bytes; frame lengths are checked
against that bound plus AEAD overhead before decoding. Manifest size/segment
multiplication is bounded by 2^40, and the zero-segment case avoids subtraction
underflow. The individual conversion paths are:

| G115 source | Verified bound before conversion |
| --- | --- |
| `archive/types.go:271` (two findings) | `validateManifest` first calls `validateContext`, which requires `1 <= ChunkSize <= 2^20`, then rejects `Segments > 2^20`. The zero-segment branch avoids subtracting one. Both `int` to `uint64` casts therefore convert positive values, and both products fit below 2^40. |
| `archive/writer.go:108` | `json.Marshal(header)` must succeed and its result must be at most 64 KiB before its length becomes `uint32`. |
| `archive/writer.go:182` | `NewWriter` validates the chunk size before allocating the buffer. `Write` fills that buffer only to the chunk size; `flush` adds 28 bytes of random-nonce GCM overhead, for at most 2^20+28 before conversion. |
| `archive/writer.go:239` | `json.Marshal(manifest)` must succeed and its result must be at most 64 KiB before its length becomes `uint32`. |
| `archive/reader.go:197` | `scan` validates the header context and rejects a frame length above its chunk-size-plus-28-byte buffer. It passes that bounded payload to `onFrame`, where its length becomes `uint32`. |

These bounds address only the named conversions. Other conversion findings
require individual review.

The G302 findings at `internal/dbsandbox/sandbox.go:108,123` and G306 at

below.

The G505 finding at `internal/utils/totp/totp.go:6` is the SHA-1 import for
`hmac.New(sha1.New, key)` in six-digit TOTP. [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238.html)

variants. The application also advertises `algorithm=SHA1` in its enrollment
URI, so switching the hash alone would break enrolled authenticators. This
does not make SHA-1 appropriate for collision-resistant hashes or signatures.
Six-digit online guessing remains bounded by the shared attempt budget, and
accepted time steps are consumed in the database; those operational controls
must remain effective across instances.

## Dependency constraints

The application does not import OpenPGP. The pinned x/crypto commit separates
the unused, unmaintained OpenPGP packages into a nested module; it does not make
those APIs safe. Keep them out of the application's graph. Dependency choices
are recorded in go.mod and go.sum; rerun govulncheck after dependency changes.
